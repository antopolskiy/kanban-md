# Principal-owner behavioral contract

This is a new project-local product-review skill. There is no predecessor skill or measured baseline.

Successful reviews:
- Evaluate the user's actual workflow need and the proposed implementation separately.
- Prefer composition and reusable operations while admitting small usability improvements and bounded core concepts.
- Identify the permanent model/config/CLI/persistence cost. Optional or generic designs do not bypass this test.
- Distinguish ordering by a property from preserving deliberate manual sequence.
- Keep basic use complete, with optional workflow policies and sensible integrity defaults.
- Retain local file authority, compatibility, non-interactive operation, and common mutation semantics.
- Use supplied evidence honestly. Mark missing support and inspect current implementation before claiming a capability.
- Give a disposition on the submitted proposal, an actionable smallest alternative where needed, and acceptance conditions or the specific missing fact.
- Keep evaluation effects simulated; no issue comments, live board edits, merges, tags, or publishing.

The test set will include independently generated feature requests plus controls for small fixes, explicit automation, ambiguous proposals, and domain/metadata tradeoffs. Expected decisions admit equivalent outcomes and are fixed before evaluation. Two fresh-context evaluators receive the same skill and cases in different orders. An independent judge checks rationale quality, missed requirements, and answer-envelope brittleness.

This contract tests decision usefulness and scope, not exact phrasing. Speculative generality, blanket rejection of new fields, mandatory two-workflow evidence, mandatory off switches for integrity, fabricated support, and empty 'needs more research' responses count against it.
